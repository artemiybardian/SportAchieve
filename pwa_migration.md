# SportAchieve: кратко о переносе TMA → PWA

## Структура

- **`backend-develop`** — API SportAchieve (к существующим маршрутам добавляется вход по email и паролю).
- **`telegram-web-app-develop`** — текущее Telegram Mini App; **не меняем**, используем как источник при копировании логики в PWA.
- **`pwa`** — новое браузерное приложение SportAchieve (установка как PWA).

## Стек PWA

| Слой | Технологии |
|------|------------|
| Сборка | Vite, React, TypeScript |
| Стили и UI | Tailwind, shadcn/ui |
| Маршруты | React Router |
| Данные с сервера | TanStack Query |
| Локальный стейт (вход, онбординг, мелочи в UI) | Redux Toolkit |
| Установка на устройство | Web App Manifest, Service Worker |
| Бэкенд | Существующий Django API + новые методы регистрации и входа |

**Авторизация в браузере:** email и пароль вместо входа через Telegram.

---

## Порядок работ (последовательно)

1. **Проект в папке `pwa`** — подключить стек (Vite, React, TypeScript, Tailwind, shadcn, TanStack Query, Redux там, где нужен токен и онбординг), настроить приложение под бренд **SportAchieve**.

2. **Бэкенд** — регистрация, вход и «текущий пользователь» по email и паролю; хранение данных пользователя в уже существующей модели пользователя (с расширением полей или отдельным вариантом — по решению при реализации).

3. **Тема и экран** — светлая/тёмная тема и обычная вёрстка под телефон и браузер без Telegram SDK.

4. **Экраны входа и регистрации** — формы email + пароль и защита остальных страниц от гостей.

5. **Связка данных** — запросы к API через TanStack Query; после входа и после оплаты/отмены подписки при необходимости обновлять списки и профиль.

6. **Перенос экранов** — список тренажёров, упражнения, профиль, онбординг: тот же пользовательский сценарий, новый внешний вид (shadcn) и загрузка данных через Query.

7. **Подписки и оплата** — нижние панели переделать под shadcn (аналог «дроверов»), те же сценарии оплаты через бэкенд.

8. **PWA** — манифест, иконки, установка с домашнего экрана; service worker для статики; не пересекаться по смыслу с кэшем запросов приложения.

9. **Сборка и запуск** — Docker и Make (или compose) для того, чтобы локально и на сервере поднимать PWA рядом с API, по аналогии с текущими скриптами.

10. **Финиш** — актуализировать документацию и скрипты так, чтобы основной сценарий разработки был через `pwa`; TMA остаётся параллельно, пока не решите его выключить.
